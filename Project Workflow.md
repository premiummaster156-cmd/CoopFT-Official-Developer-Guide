# Project Workflow

## 1. Intake
Review the Custom Bot Commission ticket, customer answers, intended use, workflows, integrations, database preferences, and timeline.

## 2. Scope
Record features, commands/events/interactions, permissions and intents, database/API requirements, security needs, exclusions, delivery format, and acceptance checks. Clarify ambiguity before development.

## 3. Policy approval
Before 500 members, the request is free and the 30-day per-member cooldown applies. After Owner Rank announces the transition, obtain an approved quote and confirm the 60% Developer share before paid work begins.

## 4. Development
Use maintainable structure, environment variables for secrets, input validation, least-privilege permissions, and clear error handling. Never commit customer credentials.

## 5. Testing
Test agreed features, permissions, invalid inputs, failure states, and setup. Never claim completion before testing.

## 6. Delivery
Prepare a ZIP with source code and setup notes: runtime version, dependencies, environment variable names (not secret values), database setup/migrations, and start instructions.

## 7. Handover
Explain customer configuration. State clearly that hosting, deployment, and 24/7 operation are not included.

## 8. Closeout
Confirm the delivered files match the scope. Record delivery and approved follow-up work in the ticket.
